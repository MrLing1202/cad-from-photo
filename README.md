## 📖 这是什么？

图纸上真正可信的东西只有一样：**人写上去的尺寸数字**。

照片有透视，打印有拉伸，像素量出来的墙线位置永远差一点。所以这套流程只认一件事——图上标的数字。

它解决两类活：

| 场景 | 你手上有什么 | 你要什么 |
|:----:|--------------|----------|
| **核对** | 一张平面图照片 + 一个已有 DWG | 逐条指出哪里画漏了、画错了 |
| **成线** | 只有一张平面图照片 | 从零生成可编辑的 DXF 线稿 |

两条路共用同一个引擎，区别只在起点。

> 🎯 不做"看着差不多"的目测比对。每一条结论都能被数字解释回来，解释不回来的会被明确标出来。

## ⚖️ 七条铁律

违反任何一条，结论就是错的。这不是风格问题，是正确性问题。

### ① 标注是唯一真值
不用图片里的墙体墨线像素当参照。像素只能告诉你"有没有这根线"，不能告诉你"多长"。

### ② 墙画的是双线，标注量的是轴线
DWG 里每道墙是两条平行线，相距一个墙厚。直接拿线段长度和标注比，会系统性多出或少掉一个墙厚。必须先做**墙皮合并**，把成对双线还原成中线再进对账。脚本已内置，`--no-merge` 只在确认图里没有双线时使用。

### ③ 轴距用轴线坐标求差，不用线段端点
门窗洞口会把墙线打断，靠端点量不出开间进深。轴线坐标两两求差，才是图上标注链量的那个东西。

### ④ 每一条标注都要带方向
横排标注量 X 方向，竖排量 Y 方向。不标方向的标注会到处乱命中——同一张图上 10640 和 12400 能在错的方向找到等值，纯属巧合。格式：`10640:H`、`8740:V`。

### ⑤ 标注得分两类
- **轴距类**：尺寸链上的开间、进深、总尺寸，跨轴命中就算对，走 `--ann`
- **单线类**：单独标在一根墙旁边的长度，必须落在同一道墙轴上才算对，跨轴等值是假象，走 `--ann-line`

### ⑥ 数值相等不等于几何成立
这是最容易骗过对账的陷阱。实测案例：图中底部那道墙标长 12400，DWG 里根本没画这根线，但另外两道墙的间距恰好也是 12400，对账会报"有"。这类必须回到位置——那个方向、那个轴段上，到底有没有这根线。

### ⑦ 无法解释比例高，先怀疑标注没收全
图上标注往往比一遍能读全的多得多。无法解释比例超 30% 时脚本会告警，看到告警就回阶段一补读，不要反过来断定 DWG 有凭空尺寸。

## 🚀 快速开始

```bash
# 1. 克隆
git clone https://github.com/MrLing1202/cad-from-photo.git
cd cad-from-photo

# 2. 依赖
pip install ezdxf pillow pywin32
```

> 💡 `pywin32` 只在需要从 DWG 转 DXF 时用到，且依赖本机装有 AutoCAD。DXF 输入不需要它。

跑一遍自带示例，确认引擎正常：

```bash
python scripts/build_dxf.py --spec examples/spec.json --out demo.dxf
python scripts/dump_entities.py --file demo.dxf --out self.json
python scripts/axis_check.py --entities self.json --from-spec examples/spec.json --outdir .
```

`examples/self_check_report.txt` 是这条命令的期望输出：**9/9 全中**。

## 🔄 工作流

### 阶段一 · 读图

原图常常是手机拍的，有透视、有阴影、分辨率不足。整张丢给视觉模型只会得到幻觉数字。九宫格切分，逐块读，关键数字定点放大复核。

```bash
python scripts/read_annotations.py --image 平面图.jpg --outdir temp/ann --grid 3x3 --scale 2.0
```

产出 9 块切片加四边条带，另可对指定坐标做放大复核：

```bash
python scripts/read_annotations.py --image 平面图.jpg --outdir temp/ann   --points "10640:820:1940;8500:1710:420"
```

**复核规矩**：总尺寸、最大开间、任何四位以上的数字，必须放大看过两遍。10600 和 10640 在一张糊照片里就是一个像素的差别。同时记下每条标注是横排还是竖排。

### 阶段二 · 标注结构化

落成一个 spec 文件。这是整条流程的锚，后面每一步都从它出发。

```json
{
  "walls_x": [0, 1600, 4400, 7200, 10640],
  "walls_y": [0, 2800, 4950, 8500],
  "thick_x": 200,
  "thick_y": 240,
  "openings": [{"axis": "x", "at": 0, "from": 600, "to": 1500, "type": "门"}],
  "ann_axis": ["10640:H", "8500:V", "3550:V", "2150:V", "1600:H"],
  "ann_line": ["12400:H"]
}
```

`walls_x` / `walls_y` 是轴线的**绝对坐标**（mm），不是间距，间距由脚本自己算。不确定墙厚的先按 200/240 填，对账阶段会显示"口径差"，那个差值反过来就是墙厚。

### 阶段三 · 把 DWG 的线抽出来

```bash
python scripts/dump_entities.py --file 原图.dwg --out temp/entities.json
```

DWG 需要本机 AutoCAD 转 DXF，DXF 直接读。输出的每条线是两端点加长度，可按图层筛选：`--layers "WALL,AXIS"`。

### 阶段四 · 墙皮合并与双向对账

```bash
python scripts/axis_check.py --entities temp/entities.json   --ann "10640:H,8500:H,2800:V,2150:V" --ann-line "12400:H"   --outdir temp
```

做两件事：

**墙皮合并** — 共线且重叠超过 75% 的成对线合并为中线，多出或少掉的墙厚在这里被消掉。

**双向对账**

| 方向 | 做什么 | 五级判定 |
|:----:|--------|----------|
| A 向 | 每条标注去找等长的墙轴距离 | 对 / 存疑 / 口径差 / 跨轴 / 缺 |
| B 向 | DWG 每条线能否被标注解释 | 单值 / 两值之和 / 两值之差 / 扣墙厚后命中 |

输出 `report.txt` 与 `axis.json`。

**读报告的顺序**：先看"缺"，那是硬伤，漏画的墙在这里；再看"存疑"，取整或读数误差，人工扫一眼；"口径差"不用管。

### 阶段五 · 成线

核对出的差异要改图，或者根本没有图要从零画：

```bash
python scripts/build_dxf.py --spec temp/spec.json --out temp/plan.dxf
```

按轴网生成双线墙体、门窗洞口断开、尺寸标注链，产物可被 CAD 直接打开。

### 阶段六 · 自检（不许跳过）

生成物必须能被自己的标注集解释回来：

```bash
python scripts/build_dxf.py --spec temp/spec.json --out temp/plan.dxf
python scripts/dump_entities.py --file temp/plan.dxf --out temp/self.json
python scripts/axis_check.py --entities temp/self.json --from-spec temp/spec.json --outdir temp
```

`--from-spec` 会自动把 spec 的轴间距、总跨、洞口宽算成标注集喂回去。**A 向必须 100% 命中。** 不到 100%，说明生成器或对账引擎有 bug，不是图纸有问题。

这一步是本方法唯一的正确性证明。跳过它就是裸奔。

## 📊 判定口径

| 差值 | 判定 | 处理 |
|------|------|------|
| ≤ 10mm | 对 | 不用管 |
| 10–50mm | 存疑 | 人工看一眼，多为取整改写 |
| ≈ 墙厚或半墙厚（≤300） | 口径差 | 净空 vs 含墙厚，正常，不判错 |
| 跨轴等值 | 跨轴 | 数值偶合，必须核对位置 |
| 其余、同轴无对应 | 缺 / 画错 | 硬伤，要改图 |

## ⚠️ 已知失效场景

- **照片严重透视**：墙线角度失真，双线合并会失效。先用 `--no-merge` 看原始轴，再人工修正 key
- **墙厚差异大**（240 外墙配 100 隔墙）：双线合并上限 300mm，两种情况都能配，但同一条轴上的不同厚度会让 key 偏移，看 `axis.json` 里的 key 值确认
- **标注被遮挡或断线**：读不全就明说读不全，不要用"图应该是对称的"去补数字，补出来的数字会把核对带偏
- **图幅只覆盖局部**：缺的墙可能本来就在图幅外，判"缺"之前先确认图幅边界

## 🧪 一份真实结果

某次实际核对：图上 62 个去重标注，DWG 145 条线。

57 个标注找到对应，其中 6 个一开始被误判成"图上凭空多出来的尺寸"，实际是标注相加相减得来的（8740 = 10640 − 1900）。剩下 12400 判缺——底部那道横向墙整个没画，DWG 的 Y 方向最低只到 −4424，而图上标注落在更下面。

这个案例说明两件事：**加减组合能解释的尺寸不要当成错；数值恰好能在别处找到等值的，也不能当成对。**
